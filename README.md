# Em 2024-2

## FATEC-API-3-SEMESTRE

### Empresa Parceira

Projeto acadêmico desenvolvido no formato de API durante o terceiro semestre do curso de Banco de Dados da FATEC São José dos Campos.

### Problema

O problema do projeto era desenvolver uma solução capaz de capturar, organizar, armazenar e consultar notícias estratégicas vindas de portais de notícias e APIs públicas.

A proposta surgiu da necessidade de lidar com informações vindas de diferentes fontes, permitindo que esses dados fossem armazenados de forma estruturada e pudessem ser utilizados futuramente para análises com inteligência artificial.

Além disso, era necessário que o sistema permitisse o cadastro e gerenciamento de informações relacionadas às notícias, como portais, APIs, tags, jornalistas e regionalismos, facilitando a consulta e a organização dos dados.

### Solução Entregue pela Equipe

A equipe desenvolveu uma aplicação web para cadastro, captura, armazenamento e consulta de notícias estratégicas.

O sistema permite o cadastro de portais de notícias, APIs, tags, jornalistas e regionalismos. Também possui funcionalidades relacionadas à captura automatizada de dados por meio de web scraping e consultas com filtros, permitindo que o usuário encontre informações de maneira mais organizada.

A aplicação foi dividida entre backend e frontend. O backend foi desenvolvido com Java e Spring Boot, sendo responsável pelas regras de negócio, controllers, services, repositories e integração com o banco de dados. O frontend foi desenvolvido com Vue 3 e TypeScript, permitindo a criação das telas e a interação do usuário com o sistema.

O banco de dados utilizado foi PostgreSQL, com apoio de ferramentas como Hibernate e Flyway para persistência e controle das migrações. O Docker foi utilizado para padronizar o ambiente de desenvolvimento.

Repositório do Projeto: https://github.com/c137santos/FATEC-API-3-SEMESTRE

## Contribuições Pessoais
Contribuições Pessoais

Minha contribuição pessoal no projeto foi voltada principalmente para o desenvolvimento e manutenção das funcionalidades relacionadas a regionalismos, tags e ao relacionamento entre esses dados dentro do sistema.

Atuei principalmente no frontend da aplicação, trabalhando na criação, organização e ajuste das telas utilizadas pelo usuário para cadastrar, visualizar e editar regionalismos. Essas funcionalidades eram importantes para permitir que o sistema classificasse melhor as informações cadastradas, relacionando regionalismos com tags específicas.

Uma das minhas principais atividades foi o desenvolvimento e ajuste da tela de cadastro de regionalismos. Nessa parte, trabalhei na estrutura da interface, nos campos de entrada de dados e na organização visual da listagem, buscando deixar a tela mais clara e fácil de utilizar. Também realizei ajustes para que a interface seguisse melhor o padrão visual das outras telas do sistema, principalmente em relação aos botões, caixas de texto e organização dos dados exibidos.

Também contribui na funcionalidade de edição de regionalismos, trabalhando no modal de edição e na correção de problemas relacionados ao botão “Editar”. Durante essa etapa, foi necessário analisar o funcionamento da tela, entender como os dados eram enviados e exibidos, corrigir problemas de duplicidade de botões e ajustar a comunicação entre os componentes para que a edição funcionasse corretamente.

Além disso, trabalhei na integração dos regionalismos com as tags relacionadas, garantindo que o usuário pudesse selecionar uma tag durante o cadastro ou edição de um regionalismo. Essa parte foi importante porque o regionalismo não era uma informação isolada dentro do sistema, mas sim um dado que precisava estar relacionado a uma tag para melhorar a organização e classificação das informações.

Durante o desenvolvimento, também realizei testes manuais para verificar se os dados eram cadastrados, listados, editados e exibidos corretamente na interface. Esses testes ajudaram a identificar problemas de funcionamento, como falhas na atualização da tela, dificuldades na edição e inconsistências na exibição dos dados.

Entre as atividades realizadas, destaco:

Desenvolvimento e ajuste da tela de cadastro de regionalismos.
Organização da listagem de regionalismos na interface.
Melhoria visual dos campos, botões e estrutura da tela.
Ajustes no modal de edição de regionalismos.
Correção de problemas relacionados ao botão “Editar”.
Correção de problemas de exibição duplicada de botões.
Integração da tela de regionalismos com as tags relacionadas.

Essas contribuições ajudaram a melhorar o funcionamento da aplicação e tornaram o gerenciamento de regionalismos e tags mais organizado, claro e funcional para o usuário.
